# CLAUDE.md — память проекта CRM

## Что это
Внутренняя CRM. Стек: Express API (`src/`) + ваниль-JS SPA (`public/js/`, БЕЗ сборщика, нативные ES-модули) + Postgres. Деплой — Vercel serverless (`api/index.js`); фронт — статика из `public/`.

## Рабочие ветки и деплой
- Разработка: `claude/creation-command-failure-HrDNn`
- Прод (с него автодеплой Vercel): `claude/build-crm-system-JzCP9`
- Поток: коммит в dev-ветку → `git merge --ff-only` в прод-ветку → push обеих → Vercel деплоит сам.
- **Превью**: каждая ветка имеет свой alias на Vercel — рискованные правки катать туда и проверять ДО merge в прод.

## Как проверять деплой
- Прод-домен: `crm-orcin-six.vercel.app`. Прямой `curl` даёт 403 (Vercel protection) — проверять через Vercel MCP `web_fetch_vercel_url`.
- `/health` и `/api/*` проходят через `ensureInitialized()` → **200 на `/health` подтверждает, что миграции прошли** без ошибок.
- **Боевую БД нельзя смотреть через Supabase MCP** — там другие проекты (`crm-prod-v2`, `crm-v3` — это НЕ прод). Прод-БД внешняя/недоступна напрямую. Для разовой диагностики данных: временный анонимный эндпоинт под `/api/...` (только агрегаты) + `web_fetch_vercel_url`, потом сразу удалить.
- Миграции/DDL — в `src/db.js` `ensureInitialized()`: идемпотентные `ALTER ... IF NOT EXISTS`, бегут на каждом холодном старте.

## Принятые решения по домену
- **Прайс — строго «канал + склад»** (`product_prices`: ключ product×marketplace×warehouse). Цена без склада запрещена: бэкенд отклоняет (`priceSchema.warehouse.min(1)`), импорт пропускает строки без склада, на старте чистятся `DELETE ... warehouse=''`. В заказе цена подставляется по площадке + складу списания.
- **Заказ**: поле «Склад списания» (`orders.warehouse`), дефолт в Интеграции→Видимость складов. «Номер отправления» (`shipment_qr`, текст) обязателен при резерве. Загрузка картинки QR убрана.
- **Потерянные товары**: возврат → «Товар потерян» (`return_status='lost'`) → раздел с суммой потерь по цене продажи, фильтр новые/погашенные, аннулирование (`loss_voided`) — только админ.

## Работа с обращениями (feedback)
- Когда я постирую ответ автору в `feedback_messages` за владельца (через временный
  diag-эндпоинт или иначе), `user_name` должен быть **«AI ассистент»**, а не имя
  реального админа. Авторы должны понимать, что отвечает бот, а не человек лично.
- Это касается только моих автогенерируемых ответов. Когда сам владелец отвечает
  через UI, его имя сохраняется как обычно.
- **Не дёргать автора повторно.** Если AI задал вопрос, а автор не ответил —
  больше не писать ему ничего по этому обращению. Один раз спросил — жди.
  Если последнее сообщение в треде от AI, новые вопросы НЕ задаём.
